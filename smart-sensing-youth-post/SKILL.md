# 智能感知青年突击队推文

## 目标

把用户提供的事实素材整理成一篇可直接编辑、排版的企业微信公众号团队通讯稿。

核心写法：**战略有高度、任务有难度、行动有细节、成果有数据、人物有声音、结尾有升华。**

文章主角默认为“智能感知青年突击队”，重点写团队如何解决问题，不写成工作流水账，也不堆砌空泛赞美。

## 使用场景

- 用户要求撰写、改写或润色智能感知青年突击队推文。
- 用户提供项目进度、攻坚记录、技术成果、团队事迹，要求整理成公众号文章。
- 用户要求仿照“青年突击队＋项目攻坚／科技创新”类企业通讯稿。

## 事实边界（必须遵守）

1. 只使用用户提供或明确可核实的事实，不虚构项目、人物、日期、数据、引语、荣誉、客户评价或主管部门认可。
2. 严格区分“已完成、正在推进、计划开展”，不得把规划写成成果。
3. 政策表述和领导引语仅在用户给出原文或可靠来源时使用；没有依据就不自行添加。
4. 技术名词可以通俗解释，但不得扩大功能、性能或应用范围。
5. 缺少关键事实时，先简短追问；用户要求先出草稿时，用醒目的【待补充】标记，不用貌似真实的细节填空。
6. 供稿、编辑、审核、图片署名等信息未提供时不编造，也不在正文中自行补写。

## 写作流程

### 1. 先提取事实清单

从素材中识别：

- **背景**：为什么开展这项任务，对应什么业务需求或发展需求。
- **主体**：团队全称，必要时补充年龄、专业构成等已有信息。
- **任务**：项目名称、建设内容、应用场景。
- **难点**：技术、工期、环境、协同、质量、安全等具体挑战。
- **行动**：团队采取了哪些办法，谁参与了关键环节。
- **成果**：完成量、效率、精度、验收、应用、获奖或用户评价。
- **人物**：真实引语、现场动作、典型瞬间。
- **未来**：已经明确的下一步计划。

素材足够就直接成稿，不机械追问已经提供的信息。

### 2. 选择文章结构

#### A. 项目攻坚型（默认）

适用于工程实施、设备安装、系统建设、应急保障、集中攻坚：

1. 总起：背景＋团队＋任务＋难点＋总体成果。
2. 部署推进：目标、分工、节点、协同机制。
3. 技术攻坚：一个关键难题＋具体解决过程。
4. 质量或安全保障：真实措施＋实际作用。
5. 成果收束：量化结果＋外部反馈（如有）＋团队感受。
6. 结尾：项目价值＋青年担当＋下一步方向。

正文设置 2—4 个小标题，可采用“行动＋目标”的对称句式，如“挂图作战，拉满进度条”，但要贴合实际内容，不为对仗而夸大。

#### B. 科技创新型

适用于新产品、新平台、算法突破、成果转化：

1. 创新背景与团队使命。
2. 已有基础或上一阶段成果。
3. 当前产品／技术的研发难点、攻坚过程和核心功能。
4. 应用价值与已落地场景。
5. 后续研发、迭代或推广计划。

按“已有成果—当前突破—未来规划”推进，避免只罗列技术名词。

### 3. 写好标题

标题同时包含“青年团队”和“核心任务”，优先使用准确、有行动感的动词。

可参考：

- `百日攻坚 青年争先——智能感知青年突击队奋战“××”项目`
- `青年先锋丨从××到××，智能感知青年突击队……`
- `智感先锋丨智能感知青年突击队攻克××难题`

默认给出一个最推荐的标题；用户要求时再给备选标题。栏目名没有确定时，不虚构固定栏目。

### 4. 写好开头

开头用一段回答四个问题：**为什么做、谁来做、做什么、做得怎样。**

- 背景只用一两句，迅速落到团队和项目。
- 难点用具体词语概括，如点位分散、工期紧、协同复杂、精度要求高。
- 总体成果有数据就写数据，没有就写已确认的事实。
- 不连续堆砌政策、口号和形容词。

### 5. 写好正文

每个重点段落尽量形成闭环：

> **遇到什么困难 → 采取什么行动 → 解决得怎样。**

写作要求：

- 多用“测试、校准、联调、排查、复盘、优化、部署”等真实动作，少写空泛的“高度重视、扎实推进”。
- 至少保留一个具体场景或关键事件，让读者看见团队怎样工作。
- 有真实引语时放入最相关的位置，用人物语言补充态度或感受；没有就不编。
- 技术内容采用“专业名称＋通俗作用”的表达，让非专业读者理解它解决了什么问题。
- 数据与场景搭配：数字证明成果，细节增强现场感。
- 图片信息已提供时，可配简洁图注，如“突击队开展设备联调”；不虚构照片内容。

### 6. 写好成果与结尾

成果段优先顺序：**核心量化数据 → 验收／应用结果 → 第三方评价 → 团队感受。**

结尾先用一句话收束成果，再上升到项目对业务、行业、区域发展或数字化转型的价值；有下一步计划时自然带出。避免连续使用多个宏大口号。

## 语言与篇幅

- 默认写成 **800—1200 字**，素材较少时宁可精简，不重复凑字。
- 采用企业公众号通讯稿语气：正式、积极、简洁，同时有现场感和青年气息。
- 每段 2—4 句，一段只讲一个重点。
- 小标题句式尽量统一，动词开头，行动与结果对应。
- 可少量使用“攻坚、突围、协同、赋能”等词，但同一句不堆叠多个口号。
- 比喻或形象化表达控制在 1—2 处，必须服务内容，避免“披荆斩棘、扬帆起航、贡献力量”等套话反复出现。
- 不夸大为“国际领先、行业首创、圆满完成、得到一致认可”，除非素材有明确依据。

## 默认输出格式

```markdown
# 标题

（总起：背景＋团队＋任务＋难点＋成果）

## 小标题一：部署或已有基础

（具体行动、节点、分工或研发过程）

## 小标题二：关键攻坚

（难点＋行动＋结果，穿插真实场景或引语）

## 小标题三：质量、安全、协同或应用

（真实措施及作用）

（成果段：数据、验收、应用或评价）

（结尾：成果收束＋项目价值＋未来方向）
```

结构服从素材：只有两个重点就不硬凑三个小标题；科技创新型文章可不用小标题，改用时间线和产品线自然推进。

默认直接输出可发布的完整稿件，不附写作分析。若有【待补充】内容，在文末另列“待确认信息”，便于用户集中补齐。

## 成稿检查

- [ ] 标题点明智能感知青年突击队和核心任务。
- [ ] 开头快速交代背景、主体、任务、难点或成果。
- [ ] 至少有一个“困难—行动—结果”的完整闭环。
- [ ] 至少保留一处具体行动、场景或真实人物声音。
- [ ] 所有数字、日期、名称、引语和荣誉均有素材依据。
- [ ] 已完成、进行中、未来计划没有混写。
- [ ] 技术内容既准确又让普通读者看得懂。
- [ ] 小标题结构统一，正文不是流水账。
- [ ] 结尾回应主题并自然升华，没有堆砌口号。
- [ ] 全文无虚构事实、无重复表达、无未经证实的夸大结论。
