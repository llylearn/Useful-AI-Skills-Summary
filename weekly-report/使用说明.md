# weekly-report：个人周报整理技能

## 1. 用途

把一周内的零散工作记录整理成“成果视图”，而不是按日期排列的流水账。输出层级固定为：

```text
项目 → 前端/后端 → 【已上线】/【开发中】→ 编号事项
```

## 2. 触发方式与输入

用户提到“周报 / 个人周报 / weekly report”，并同时提供本周工作记录时使用。示例：

```text
生成本周周报：
订单服务【后端】【开发中】完成订单查询接口，联调中；
基础数据【前端】地下通道、路域信息等十五个列表已上线；
同一任务周一50%，周三100%。
```

只问“周报怎么写”而没有工作记录时，不属于本技能的正式执行场景。

## 3. 关键整理规则

- **合并重复任务**：同一需求从50%推进到100%，最终只保留一条成果。
- **不带进度百分比**：百分比只用于判断状态，不进入周报正文。
- **标签优先**：明确标了【开发】或【开发中】的事项，即使文字出现“交付/100%”，仍按开发中处理。
- **保留业务信息**：合并多个页面时保留模块名和总页面数；不编造原记录没有的数量。
- **精简技术细节**：接口参数值、变量名、文件路径和组件英文名不直接搬进周报，可转成中文业务描述。
- **不留空标题**：没有后端工作就不写“后端”，没有已上线事项就不写“【已上线】”。
- **控制篇幅**：通常10—20条；重要、完成度高的事项排前。

## 4. 输出要求

默认在对话中给出纯文本周报。用户要求落盘时，保存为桌面上的 `周报_<日期>.txt`：

- 文件名不带“个人”。
- 内容与对话正文一致。
- 本机默认桌面为 `~/桌面`；可通过 `DESKTOP_DIR` 环境变量覆盖。

## 6. 新机器恢复与验收

复制到 `~/.dsh/skills/weekly-report`。DSH 会监视该目录并刷新技能目录；在 dsh-tui 中可用 `/skills` 检查。验收时重点检查：所有原始记录都有归宿、无重复任务、无百分比、端别和状态正确、项目名保持用户原叫法。
